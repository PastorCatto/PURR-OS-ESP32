Steps (fonttools 4.60.2):

  1. Fix the weight at the regular master (Tiny TTF draws the default outlines and ignores variations, so the
     variation tables would be dead weight):
       python3 -m fontTools.varLib.instancer "NotoEmoji[wght].ttf" wght=400 -o NotoEmoji-400.ttf
     (886,628 bytes for all 1,489 code points)

  2. Subset to the core set listed in core-set.txt (414 code points, 415 glyphs with .notdef):
       python3 -m fontTools.subset NotoEmoji-400.ttf --unicodes-file=core-set.txt \
         --layout-features= --no-hinting --name-IDs='*' --notdef-outline \
         --drop-tables+=GSUB,GPOS,STAT,vhea,vmtx,gasp,GDEF --output-file=NotoEmoji-core.ttf

Result: NotoEmoji-core.ttf, 191,612 bytes, sha256 b755ca74c4bdc5c9e2fafc4f82ae5a4f817ab31eb758056d2cac136eca01ab87.

The core set (core-set.txt has the groups with comments): all faces and cat faces, gestures, hearts, hands, a few
animals (cat, dog, paws), weather and nature, food and drink, the objects the shells talk about (phone, mail, folder,
lock, battery, bell, speaker, tools), symbols (ticks, crosses, warning, arrows, media controls, coloured circles and
squares), a few places and sport items, ZWJ and the variation selector. Flags, skin-tone modifiers, keycaps, regional
indicators and the long tail of the full set are left out. Tiny TTF does not shape ZWJ sequences, so a family or
profession emoji would show as its parts; those sequences are not in the set.

The subset keeps the font names and the copyright and licence strings in the `name` table.
